1. EXECUTIVE SUMMARY & VISION
===============================================================================
Finding high-value, legitimate freelance and contract development opportunities
manually requires monitoring dozens of remote boards, community threads, and RSS
feeds. Developers lose countless hours parsing noise, evaluating requirements,
calculating market compensation fit, and crafting bespoke proposals.

CLIENT FINDER SVC automates this entire lifecycle into an intelligent, high-velocity
pipeline:
- Ingests opportunities continuously from Hacker News, RemoteOK, WeWorkRemotely,
  and arbitrary RSS/Atom feeds with autonomous circuit-breaker fault tolerance.
- Strips HTML and normalizes dirty text data.
- Extracts structured schemas (required skills, budget, deadline, client credibility)
  using LLM extraction with deterministic regex/heuristic fallback.
- Detects duplicates across titles and URLs using SHA-256 cryptographic hashes.
- Matches opportunities against developer proficiencies using a hierarchical
  synonym taxonomy graph.
- Calculates explainable multi-factor match scores (0-100) and historical win rates.
- Dispatches instantaneous alerts via Discord, Slack, SMTP Email, and Desktop toasts.
- Generates tailored proposals citing matching developer portfolio case studies.
- Tracks proposal lifecycle progression through a 12-stage conversion funnel with
  Bayesian win-rate calibration.

2. ARCHITECTURAL LAYER OVERVIEW
===============================================================================
The system is constructed with strict separation of concerns across 15 modular
subpackages in `src/`:

- `src/ai/`          : LLM client providers (OpenAI, Gemini, Ollama) and extraction schemas.
- `src/analytics/`   : Funnel conversion metrics, velocity, and win-probability calibration.
- `src/api/`         : FastAPI REST application, 11 route routers, and static glassmorphic UI.
- `src/collectors/`  : Multi-source feed harvesters, registry singleton, and circuit breaker.
- `src/database/`    : SQLAlchemy 2.0 ORM models, migrations, and repository layer.
- `src/matching/`    : Skill matcher, taxonomy synonym dictionary, and implied skill graph.
- `src/models/`      : Core domain models (Project, UserProfile, SkillProficiency, PortfolioProject).
- `src/notifications/`: Multi-channel notification dispatcher, rate limiter, and channel adapters.
- `src/processors/`  : Data cleaners, URL extractors, and text normalizers.
- `src/proposal/`    : AI proposal generator, prompt engineering, and heuristic fallback engine.
- `src/scheduler/`   : Autonomous pipeline coordinator and background recurring daemon thread.
- `src/scoring/`     : Multi-factor opportunity scoring algorithms and score breakdowns.
- `src/tracking/`    : 12-state application lifecycle tracker and progression schema.
- `src/utils/`       : HTTP client with backoff retries, date/currency utilities, and formatters.

4. DATA PIPELINE & END-TO-END EXECUTION FLOW
===============================================================================
When `PipelineCoordinator.run_cycle()` executes:

1. COLLECTION: Active collectors (`Hacker News`, `RemoteOK`, `WeWorkRemotely`) harvest listings.
   Collector health telemetry (`success_count` or `failure_count`) is logged in `CollectorRegistry`.
2. CLEANING: `clean_project_data()` normalizes unicode, trims whitespace, and strips HTML markup.
3. EXTRACTION: `ProjectExtractor.extract()` extracts required skills, budget numbers, and project type.
4. PERSISTENCE: `ProjectRepository.add_many()` computes SHA-256 hashes; existing items are skipped.
5. SCORING: `OpportunityScorer.score_and_persist()` calculates multi-factor score and win probability.
6. DISPATCH: If overall score >= min_notification_score (default 75.0), alerts are dispatched.
7. CONVERSION: User reviews leads in web dashboard or CLI, crafts tailored proposals with portfolio RAG,
   and progresses applications through the tracking funnel.

6. SCORING ENGINE MATHEMATICAL FORMULATIONS
===============================================================================
Composite Opportunity Score:
  Score = (0.35 * S_skill)
        + (0.20 * S_budget)
        + (0.15 * S_client)
        + (0.10 * S_competition)
        + (0.10 * S_complexity)
        + (0.10 * S_freshness)

Where:
- S_skill       : Evaluates primary/secondary match ratio and proficiency ratings (1-10).
- S_budget      : Evaluates hourly rate and fixed budget fit relative to developer target.
- S_client      : Checks client name clarity, contact transparency, and risk indicators.
- S_competition : Penalizes over-applied platforms; boosts low-competition niches.
- S_complexity  : Rates architectural alignment with developer target seniority.
- S_freshness   : Exponential recency decay based on hours elapsed since posting.

Win Probability Calibration:
  P_calibrated = P_base * M_skill * M_pitch
  where M_skill in [0.5, 2.0] and M_pitch in [0.7, 1.5] are updated empirically from won/lost outcomes.

7. PORTFOLIO CASE-STUDY RAG & PROPOSAL GENERATION
===============================================================================
The developer profile (`UserProfile`) contains verified past project case studies (`PortfolioProject`).

Dynamic Retrieval Flow:
1. `UserProfile.find_relevant_portfolio(target_skills, max_results=2)` ranks past case studies
   by technology tag overlap and description keyword matches.
2. Top matching case studies with quantified business outcomes (e.g. "Reduced support latency by 65%")
   are formatted into the LLM system prompt and heuristic templates.
3. The generated proposal subject line, opening hook, architectural approach, and CTA directly
   cite past proven achievements matching the client's exact stack.

9. APPLICATION LIFECYCLE STATE MACHINE (12 STAGES)
===============================================================================
1. LEAD                 : Discovered opportunity qualified for application.
2. PROPOSAL_DRAFTED     : AI proposal generated and customized.
3. SUBMITTED            : Proposal transmitted to client.
4. VIEWED               : Client confirmed viewed proposal.
5. SHORTLISTED          : Client shortlisted candidate.
6. INTERVIEW_SCHEDULED  : Interview confirmed.
7. INTERVIEWING         : Active interview process in progress.
8. OFFER_RECEIVED       : Contract offer extended.
9. NEGOTIATING          : Rate or scope negotiation.
10. WON                 : Contract signed / milestone commenced (Terminal Success).
11. LOST                : Opportunity closed or rejected (Terminal Closed).
12. WITHDRAWN           : Candidate withdrew application (Terminal Closed).

Automated timestamps (`applied_at`, `response_at`, `interview_at`, `closed_at`) enable
rigorous conversion funnel velocity and drop-off analytics.
